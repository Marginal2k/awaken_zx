# STORM-origin modules (awk2 / awk4 / awk5) - restored to sjasmplus

Everything below is regenerated by `python tools/storm_gen.py` (decode + convert, writes `src/storm/**`) and checked with
`python tools/verify_storm.py` (needs sjasmplus 1.23).  Support files: `tools/convert_storm.py` (the converter),
`tools/storm_detok2.py` (storm_detok.py with one decoder fix, see 2), `tools/storm_find.py` (searches the disks for chunks of a module).
Scratch output: `work/storm/{decoded,out,tmp}`.

**Status after the readability pass (this block is now hand-maintained)**: `src/storm/*.asm` were reformatted (lowercase mnemonics, aligned
operands, sentence-case Russian comments, one header per module), 181 label definitions got English names (old name kept as `; orig: NAME`;
table in `docs/STORM_LABELS.md`), 129 loop-jump labels became local `.labels`, hardware constants moved to `src/storm/HW.asm`
(ports `PORT_PAGE`, `PORT_AY_REG`, `PORT_ULA`, TR-DOS `TRDOS_COMMAND`, screen `SCREEN*`) and engine constants to `EQUS.asm`
(`OBJ_LEN`, `PAGE_3D`/`PAGE_VOXEL`/`PAGE_NORMAL`, `VOX_*` and `ENG3D_*` entry tables).  Output bytes are unchanged (`verify_storm.py all`,
sha256 of every `make_*.asm` binary).  **Do not re-run `tools/storm_gen.py`: it would overwrite the cleaned sources with raw converter output.**
The names used below in sections 2-6 are the original STORM names; look them up in `docs/STORM_LABELS.md`.
Modules without a `make_*.asm` (BLK*, NXT, SERV, XR2_lc, and the parts XR1/XCLP/BLOK1/OBJX/VOXL/VOXP/DATAM/LOADER) are fragments, built only inside their parent
(S3D, VSPRITE, LAND) or checked as fragments by `verify_storm.py frag`.  `python build.py --storm` assembles every `make_*.asm`.

## 1. What the STORM material is

STORM was the author's assembler before ZASM.  The STORM era (1997/98) is the **prototype** of Awaken: a planet-landing
interlude with skimmers (hover cars), houses, trees and a voxel landscape.  Its 3D engine is the common ancestor of the
flight engine (awk1) and the station engine (awk6).

| disk | files | form |
|--|--|--|
| awk2 | 28 sources (type C, start #C00B) + data blobs + two compiled pages `S3D.C`, `VSPRIT.C` + raw page dumps `PAGE3`/`PAGE4` | STORM tokenized |
| awk4 | 18 type-C files with start==length | STORM's own plain-text export, **identical** to the awk2 decodes (check `verify_storm.py texts`); `LAND`+`LAND2` and `XR2`+`XR22` are one source cut in two halves |
| awk4 | `LAND XR1 XR2 S3D ...` ZASM forms | ZASM `convert` output, half converted, ignored (they carry nothing the text export does not) |
| awk5 | `LOAD`, `LOAD+`, `INVDISK` | STORM tokenized.  Everything else on awk5 (PRESNT, EFECT*, EFF*, SOUND*, p*/s* screens, SAM*, SP, AX3 ...) is binary only: **no source for the intro/presentation code exists on any disk** |

## 2. STORM dialect facts established (all verified against `S3D.C` / `VSPRIT.C`, byte exact)

* Expressions use normal priorities (`PP1+6*2` = `PP1+12`; left-to-right gives nonsense and a failing build).
  `\` remainder, `!` OR, `|` XOR, `&` AND, `=` equality, `<< >>`.  Postfix: `x[` high byte, `x]` low byte,
  `x^` round up to the next 256 (`ORG $^`; emitted as `($+255)&#FF00` - matches all cases that occur), `` x` `` round down (`` ORG $`+#C0 ``).
* A line starting with `.N` is **not a local label**: it repeats the whole rest of the line N times (`.8 RL E:RLA:SUB D:JR NC,$+3:ADD A,D`, `.32 PUSH HL`,
  `.16 DW ...`).  -> `DUP N ... EDUP`.  There is no `=N` reference anywhere in the corpus.
* `ORG a,b` = code runs at `a`, is placed at `b` (`ORG ADHIDE,$` in LAND) -> `ORG b` + `DISP a`, `ENT` before the next `ORG`.
* `_` before a mnemonic = "not tabulated" (cosmetic).  `OUT r` = `OUT (C),r`, `IN r` = `IN r,(C)` (AY port code in LAND), `OUT (n)` = `OUT (n),A`.
  Multi operand `PUSH/POP/INC/DEC a,b`, `LD A,B,C,D` pairs, `LD rr,rr'`, `EX HL,DE`, `ADD DE,HL`, `HX LX HY LY` register halves, `SLI`, `EXA`, `INF`.
* **Decoder bug found**: `tools/storm_detok.py` prints the conditional jumps with PO/PE/P/M (command bytes 7C..7F) as `CALL`.  They are `JP`
  (`FA F2 EA E2`); real `CALL P/M` is the `51` (CALL) prefix + condition.  `storm_detok2.py` fixes this; the result equals the awk4 plain-text export
  line by line (that export prints `JP P,...` and one `CALL P,Lm1`).
* Labels may contain `_`; `ADHIDE EQU 0-#1388` needs 16-bit wrap (`#10000-#1388` in the source).
* No macros, no IF/REPT directives occur in the corpus (the converter still supports IF/IFU/IFNU/IFD/IFND/ELSE/EIF/REPT).
* Labels equal to sjasmplus keywords get a trailing `_` (`END` -> `END_`).

## 3. Per-module status

Layout of the sources: `src/storm/<NAME>.asm` (TR-DOS name; the older `xR2` = `XR2_lc.asm`), `src/storm/awk5/`, data blobs `src/storm/assets/`
(only files that are `INCB`ed; `D9000+` -> `D9000_plus.bin`, `drv2` vs `DRV2` -> `drv2.bin` / `DRV2_UC.bin`), build drivers `src/storm/make_*.asm`
(`DEVICE ZXSPECTRUM48`, STORM compiled into memory and the span was saved: `SAVEBIN`).

| module | what | status |
|--|--|--|
| **S3D** (+ EQUS, XR2, XCLP, XR1, BLOK1, OBJX, D9000, D9200, korni) | 3D object engine page #C000/#FF00 (jump table at #FF00: INIT_, OUTAL2_, NXTO_, ADI3D_, Moveon, Precord, Nulmove, Fline) | `make_S3D.asm` **byte exact** vs `awk2/S3D.C` (16151 bytes) |
| **VSPRITE** (+ VOXP, VOXL, VOX2) | voxel sprite/landscape renderer page, entry table at #C000 (Vox, TAKSPD, OUTALL = CLER+LAND+SKY+MOVING+NIGHT, NEWPOS, NEWPSS, RETURN, RRT, RLT, D3D2) | `make_VSPRITE.asm` **byte exact** vs `awk2/VSPRIT.C` (8056 bytes) |
| LAND (+ LOADER, DATAM, EQUS, planet/CHAN6/DRV1/DRV2/DOMA1/FONT) | the planet surface + sky program at #7C00 | builds (`make_LAND.asm`, 0 errors); no compiled copy on any disk -> cannot be byte checked.  awk4 `LAND`+`LAND2` text equals it line by line |
| EQUS | constants of the whole engine (object record Olen=#20, Type/Mode/Energy..., VARS #6700, pages PG3D #11 / PGSPR #13 / PGNORM #10, jump tables of both pages) | included everywhere; identical awk2/awk4 |
| DATAM | 28 trade goods / 31+14 weapon tables / 50 persons (`PKOL`), Russian shop texts | builds inside LAND |
| LOADER | loads `VSPRIT.C` into page #13 and `S3D.C` into page #11 via TR-DOS #3D13 | builds inside LAND |
| XR2 (disk "XR2", 10427 b) | polygon rasteriser / 3D transform | exact inside S3D after the ED_ patch (4.) |
| xR2 -> `XR2_lc.asm` (10029 b) | older XR2, still defines `INIT` itself (no `INIT_`) | converts cleanly; belongs to an older S3D that is not on disk, does not build with the current EQUS (`Duplicate label INIT`) |
| XCLP, XR1, BLOK1, OBJX | clipping, view/object loop, collision/control, object (vertex/face) data | exact inside S3D |
| NXT | **byte-for-byte same text as XR1** (same length 4272) | duplicate |
| BLK1 BLK2 BLK3 BLK5 BLK6 BLK7 | older split of the engine (object control/Moveu, rockets/Newrokt, Datal, Korni, Precord, visibility/Vsline) | convert cleanly (BLK3, BLK5 resolve completely); labels of modules that do not exist on disk (Counter, Speed, Indx, Status, Roketn*, Eff*, ...) are missing, so they cannot be linked.  BLK3 is contained in LAND, BLK5 in S3D |
| SERV | mouse/keyboard driver ("MOUSE DRIVER FROM ZX-FORMAT": Directz, Mports) | converts cleanly, needs KUP/KDOWN... of the missing main program |
| VXXX | experimental voxel sprite with scaling/transparency, precursor of VSPRITE | builds (`make_VXXX.asm`) |
| VOXEL | older voxel renderer test program | builds (`make_VOXEL.asm`) with the two `INCL "CSIZE"/"CMOVE"` commented out; **CSIZE and CMOVE are on no disk** (not even as deleted directory entries) and are not needed to assemble |
| CNVVOXS3 CNVVOXSP CNVVOXTB | one-shot voxel sprite converters (nibble `#0X`->`#XX`, table de-interleave) | build (`make_tools.asm`) |
| INVTAB3D | turns the texture mask table `D9000+` into `D9000` | builds; algorithm checked byte exact on the data (`verify_storm.py inv`) |
| awk5 LOAD, LOAD+ | raw FDC (ports #1F/#5F/#FF, no TR-DOS) loader that streams screen/animation frames, `MAKEDRP` builds unrolled screen drop code at #EC78 | build (`make_LOAD*.asm`), no compiled copy |
| awk5 INVDISK | inverts (CPL) 159 sectors in place via #3D13 | builds.  **Note**: this is a disk "protection"/obfuscation tool - not used by the build |

Gap bytes: STORM saves a memory span, so alignment padding (`ORG $^`) contains whatever was in memory (stale source text, 522 non-zero bytes in
S3D.C); `verify_storm.py` builds twice with different memory fill to identify those bytes and does not count them.  Everything else is identical.

### Differences explained
1. `S3D.C` was compiled from the XR2 state that is also in the awk4 text export (`JP NC,Ld73d` x2, `JP NC,Ld73c` x2).  The disk file `XR2` is newer
   (it jumps to `ED_`, the emergency exit of VSPRITE, which does not exist in the S3D build).  `storm_gen.py` patches the four lines back (documented in the header
   of `src/storm/XR2.asm`).  This is version drift, not a converter problem.
2. Gap padding as above.
3. LAND, VXXX, VOXEL, LOAD*, tools: no binary exists, only assembly without errors can be shown.

## 4. Where it fits in the game (compared with the final code)

Source-level similarity (share of normalized code lines of the final module that also occur in the STORM text):

| final module | best STORM ancestor |
|--|--|
| awk6 `XR2` (station, in D3D.C) | XR2 70 % |
| awk6 `CLPXR1` | XCLP 66 % (+XR1 37 %) |
| awk6 `OBJX` | OBJX 49 % (object data D3D.C: 90 % of the OBJX data bytes of S3D.C are found, shifted by 819) |
| awk6 `DATA3D`, `DATA_M`, `LOADER` | S3D head 27 %, DATAM 23 %, LOADER 32 % |
| awk1 `3D-II` (flight engine) | XR2 76 % |
| awk1 `3D-I` | XR1 48 % (awk3/awk4 `3D-I_`: 66 %) |
| awk1 `VOXEL` (flight voxel sprites, VOXAL page) | VSPRITE+VOXP+VOXL 54 % |

* Binary level: `awk6/D3D.C` (= demo v0.2 `D3D.C`) shares with `S3D.C` exactly the first #800 bytes (D9000/D9200/korni tables at the same addresses) and the
  object data block; the code is re-assembled with different addresses.  `VOXAL.C` (flight page) contains chunks of VSPRITE (23 %).
  `ACTION.C`/`SP.C`/`SPACE.C` and `KARTA.C` share small math kernels (tables / multiply / divide) at other offsets.
* **S3D, VSPRIT, LAND, PAGE3, PAGE4, LOAD, INVDISK are not in demo v0.1, v0.2, AWAK_SDC or SPACE** (searched with `storm_find.py` over all extracted files incl. BANK*/BD*:
  no hit above 5 % apart from the shared tables and math).  They were never shipped; the STORM era is purely developer history.
* `awk6/D3D.C` (DATA3D XR2 BODY3D CLPXR1 OBJX) **supersedes** S3D.C (engine + tables + objects); awk1 `3D-I/3D-II/VOXEL` supersede XR1/XR2/VSPRITE for flight;
  nothing in the final game supersedes **LAND** (landing, skimmers, sky, night, sound effects, HUD text routines) - it is the only functionality of the prototype
  that is absent from awk1/awk6.
* How LAND works: START clears the screen, LOADER pulls the two engine pages in, `MAKEDRP` builds the unrolled "drop" screen code (DROPSCR, relocated to ADHIDE),
  `DALEE` initialises 40 object records (`A3D`), generates skimmers (`GENS`), then the main loop `M2` = `OUTALL` (page #13: clear, land, sky, moving, night) +
  `OUTALL2` (page #11: 3D objects: Sturm/Istr/Turi/Trad vehicles, trees DREVO1/2, house DOM1) + `INTEL` (AI modes) + sights + AY effects + panel/timer; Space =
  exit.  On exit it reloads `PAGE4` into page #14 and `PAGE3` into page #13 (dumps of the flight pages, i.e. the landing was an interlude inside the flight game).

## 5. Recommendation

1. Keep `src/storm` as a self-contained "prototype / landing demo" source set, not part of the main disk build; it is documented, converter-reproducible and
   passes `verify_storm.py` (S3D, VSPRITE exact).  Do not let it touch `src/flight` / `src/station`: the names (EQUS, XR2, OBJX, LOADER ...) collide with the
   final modules, which is why everything stays in `src/storm` with its own EQUS.
2. Do not merge S3D/XR*/XCLP into the final game: D3D.C and awk1 are the newer descendants of these files.
3. If a landing scene is wanted, LAND is the only candidate and must be integrated as a third "overlay program" like HELP/KARTA/LANG, not into the main image:
   * needs RAM pages #11 (S3D) and #13 (VSPRITE) which the flight game uses for CONTR/VOXAL, so the flight pages have to be reloaded afterwards (as `EXIT` does with PAGE3/PAGE4 -
     these are old dumps and unusable; the final flight needs its own reload, e.g. through the awk1 LOADI2 file loader);
   * the program lives at #7C00 and uses VARS #6700, i.e. it replaces the main image - same constraint as ACTION/STATIONF;
   * needs a disk layer (`VSPRIT.C`, `S3D.C` as `make_*` outputs, plus the loader names in `LOADER.asm`) and an entry/return convention from the flight code (none documented).
   Because no compiled LAND exists, the first step is an emulator run of the freshly built LAND + VSPRIT.C + S3D.C on a test TRD to confirm that it runs.
4. `VXXX`, `VOXEL`, `BLK*`, `NXT`, `SERV`, `xR2`, CNVVOX*, INVTAB3D, LOAD*, INVDISK are history/tools; keep them for reference only.

## 6. Open questions

* `ED_` in the newer XR2: purpose in the S3D build unknown (probably a hook for a later VSPRITE-based build).
* `CSIZE`, `CMOVE` (included by VOXEL): not on any disk.
* Contents of PAGE3/PAGE4 (raw page dumps) and how they relate to the final flight pages: no match with any awk1 file.
* Source of the intro/presentation binaries on awk5 (PRESNT, EFECT1/2, EFF*, SOUND*): not present; only the loader LOAD/LOAD+ is.
* LAND byte verification would need a compiled copy; none found on awk2/awk4/awk5 or in the reference demos.
