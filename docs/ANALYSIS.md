## 2. ZASM language notes
- Expressions are evaluated strictly left to right, no precedence (`YEND+1/2` = `(YEND+1)/2`);
  the converter adds parentheses.
- Postfix `.h` = high byte, `.b` = low byte, `.e` = low<<8. `inc/dec/push/pop a,b,c` take several operands.
  `ifp` = "macro parameter given"; macro params `=1..9`. Auto labels `$M/$J/$R/$P<n>`.
- No project file. The master source (SPACE on awk1, DOS on awk6, METHOD on awk3/4) uses
  `include "X"` (source by TR-DOS name), `insert "NAME.ext"` (binary, type = first letter of ext),
  `org`, `phase/unphase`, `make "F.C",A` (close the previous output, start a new one at A), `saveobj`,
  `makelab "LABELS"`, `if ASM ... else insert "X.C" endif` (ASM ON builds everything, OFF reuses
  old binaries + LABELS). The 22/137-byte `compile.e` files are scratch of the compile overlay.
- Converter mapping: make/saveobj -> savebin under DEVICE ZXSPECTRUM128, phase/unphase -> disp/ent,
  ent/create/makelab -> comments, `$M5` -> ZM5, labels that clash with keywords get `_`
  (END -> END_, PAGE -> PAGE_), `ifp` macros split into NAME / NAME__NOARG,
  `.e` -> low(x)*256.

## 3. Match against binaries on the developer disks (sjasmplus 1.23)
awk1/SPACE.asm and awk6/DOS.asm assemble with 0 errors.

| module | result |
|--|--|
| awk1 3DPART.C, CONTROL0.C | byte-exact |
| awk1 DATAS.C, OBJECT3D.C | byte-exact when the line `;  db#33,#5F,#55,#50` in OBJECTS is active (`--variant objects_line`): the binary predates the author commenting it out. LABELS then matches 464/465 (NEXTL1 differs) |
| awk1 CONTROL.C | 2 bytes (`ld (PWOPK+1),a`, #7A9D vs #7A8D): source newer |
| awk1 VOXAL0.C | ours 256 bytes shorter: GMATRX after ANBY2 rewritten after the binary was built |
| awk1 VOXAL.C | 146 bytes, all +1 high bytes of refs into VOXAL0 (consequence of the above) |
| awk6 HELP.C / KARTA.C | 8 / 98 bytes, only absolute refs into the main image: main-image modules are newer |
| awk6 D3D.C / LANG.C | 15722 vs 15978 / 4051 vs 4204: sources newer |
| awk3/awk4 METHOD | assembles, no binaries to compare |

Demo v0.2 binaries (DATAS, CONTROL0, CONTROL, 3DPART, STATIONF, ACTION) are older than all sources;
VOXAL0, OBJECT3D, PANEL, stscr are byte-identical to the awk1/awk6 copies.
STORM-origin modules (LAND, S3D, VSPRITE, XR1, XCLP, VOXL, BLOK1, DATAM ...) are decoded only;
their awk4 ZASM forms are half-converted and do not build.

## 4. Version map
- awk3 = byte-identical subset of awk4 (redundant).
- awk1 = newest 3D flight code. The `_` modules on awk3/4 (BODY_, CLIPMAT_, 3D-II_, 3D-I_, 3DTABS_,
  OBJECTS_, INIT_) are the older pre-game engine. awk1 has two voxel renderers: vOXEL (older) and
  VOXEL (included by SPACE).
- Station part: STORM (awk2) -> ZASM conversion (awk4, partly mangled) -> clean awk6 = final.
- awk6 LANG/D3D/KARTA/HELP are newer than the demo v0.2 binaries.

## 6. Disk I/O and protection
TR-DOS #3D13 (`ld a,3`/`ld c,#0E` read file, 9-byte names at #5CDD such as "VOXAL0  C"), #3D2F exit.
- awk1 LOADI2: RRFILE, RDFILE, PAGE macro, DEHRUST (Hrust unpacker for PANEL); SETHJRET/TUNEL/DOOM jp #3D2F.
- awk6 LOADER: KARTA, MUZ1, stscr, HELP, D3D, LANG + SECTAB `db 13,11,11,12,8,14,19,15,15,13,19,12,16,20,21,20`,
  random stscr choice from `ld a,r`, TR-DOS variables #5CEA/#5CEB.
- No save/load-game code in the sources (demo SAVE0-5.s are 512-byte records).
- No protection found in the sources; the demo AWAKEN.B payload is not checked yet.

## 9. Phase 2a - glue recovered from demo v0.2 (partial)

Boot chain of the demo:
1. `AWAKEN.B` = `10 REM <code>` / `20 RANDOMIZE USR 23873`... the REM code (#5CD0): `di; ld sp,#5FFF; ld iy,#5C3A; push #6500; ld de,(#5CF4); ld b,#2C; ld c,5; jp #3D13`
   = TR-DOS read of the 44 following sectors of its own file to #6400, return to #6500.  The payload (file offset #100.. = `work/boot_payload.bin`, 11 K) is an
   **intro animation** (screen copy to #4000, tunnel/scroller effect routines at #66xx-#7Exx, music hooks); at its end it copies `"STATIONFC"` to #5CDD,
   `ld c,#0A / #08` (find + catalogue entry), then `push #6300; ld hl,#6000; ld de,(#5CEB); ld b,#C0; ld c,5; jp #3D13` = reads 192 sectors of STATIONF.C to #6000 and enters it at **#6300**
   (= `ent` of awk6/DOS: BODYOCUR).  No protection, no disk check anywhere in it.
2. Station -> flight: the demo's STATIONF.C contains (not in any awk6 source) a stub at #8170-#81B3: page #18 select, name `"ACTION  C"` (at #81B4) copied to #5CDD **via a block executed at #4200**,
   `ld c,#0E; call #3D13` (loads ACTION.C to #6000), then `ld hl,#4000; ld de,#9BBD; ld bc,#200; ldir` = **512 bytes of game state** (the same size as `SAVE0-5.s`, 512 bytes at #6000)
   are copied from #4000 into the station/flight shared state block at #9BBD, `ld sp,#6000; jp #6000` (= LOADI2 of the flight image).  Similar code exists for `FINALF  C` (ending, at #7119) and `SAVE1  s` (#77DC).
3. Flight -> station: ACTION.C (#7440-#745F) copies #1E1 bytes of state to #9BBD, sets 4 flags (#9B79=#FF, #9B7A=5, #9B7C=#FF, #9B7F=0) and `jp #6000`; the station reload is done by code
   behind the string `"ACTION  C"` at #7462 (the flight image carries the file name list `VOXAL VOXAL0 CONTROL CONTROL0 PANEL OBJECT3D`, i.e. LOADI2).
4. The newest sources (awk1/awk6) contain **none** of this glue: no source references `ACTION`, `STATIONF`, `FINALF`, `SAVEn`; all labels resolve inside their own tree.  Flight<->station switching,
   save/load and the ending are therefore not in the restorable sources; they exist only in the demo's older images (STATIONF/ACTION), whose addresses differ from the newest sources (state block #9BBD vs DATA_M `PLACE`=#9647 etc.).

Status of the phase 2a build (see README): `python build.py` produces `build/awaken.trd` with boot stub (new, `src/boot/boot.asm`), station part, flight part and assets, but there is **no launcher
between the two parts** yet and the boot has NOT been emulator-tested (the br emulator harness no longer fits the current ZX-M8XXX: `zxDebug` was removed and `window.spectrum` is not exposed in v26.11.02 -
tools/emu/scripts/awk.js is a first adaptation, unfinished).
Disk layer: `src/common/disk.asm` (TRDOS_* equates, DISK_SETNAME/DISK_LOAD/DISK_READ/DISK_FIND/DISK_INFO/DISK_RDSEC/DISK_EXIT, `DISK_SECTAB`); flight `LOADI2`/`SETHJRET` and station `LOADER` use only these.
The SECTAB data line was disabled (space-led comment) in the last saved awk6 source but is present in the demo binary -> restored in disk.asm.
